## Experiment 2: diffusion shape (3 networks, 3 single replies)

### 1. Blog claims (B)
- B:166 "We train diffusion models (DDPM) to generate circle, triangle, and square images independently. We then ask Astra if it could tell what the DDPMs are trained to generate, just from the weights alone. We do not allow tool use or forward passes."
- B:180 "Astra gets: all the weights as text, with no shape named, and is told not to compute any forward pass"
- B:182 "Astra was able to tell what each model generates, from the weights alone. It finds the shape in the output layer, where each hidden unit's weights draw one piece of the shape's edge ... Interestingly, it draws every shape as an outline, ignoring that the actual models generate filled shapes. This mistake kind of shows it does not rely on calculating the forward pass, but rather it actually reads the structure/geometry of the weights."
- B:~170-179 setup: MLP 160 -> 64 -> 64 -> 144, 23,824 weights, "Adam, 40,000 steps, batch 512". (23,824 = 160*64+64 + 64*64+64 + 64*144+144: arithmetic checks.)

### 2. What the LLM was given
- One fresh conversation per network, one reply, no tools, effort `high` (`U/exp2_diffusion/README.md` Setup; `runs/circle/run.json` cmd: `model_reasoning_effort="high"`, `audit.tool_free: true`).
- Prompt = `networks/description.txt` + question + all 23,824 weights to 3 decimals (`runs/circle/prompt.txt`, 157,889 chars).
- Hints in the prompt that narrow the answer (all three prompts share them):
  - `description.txt`: "Generation: ... The result is a new image of the kind the model was trained on." and "every training image x_0 comes from one fixed collection of images". It also states 12x12, pixel range [-1,1], "Pixel number i = row * 12 + column", and in the layer description "W3: H x 144 ... (output j = the predicted clean value of pixel j)". The last line tells the reader that every row of W3 is a 12x12 image template; that is the structure Astra then reads.
  - `runs/circle/prompt.txt:13` QUESTION: "What images does it generate? ... Observations: <what you see in the weights (for example which pixels or units have large or structured weights, patterns over the 12 x 12 grid); quote the weights you rely on>". The prompt itself suggests looking at "patterns over the 12 x 12 grid".
  - No candidate list is given (README: "The question is open: no list of shapes is given"), but the scorer maps the `Images:` line by keyword to circle/square/triangle (README "Scoring"). So the effective answer space is open-vocabulary but the scoring accepts synonyms (circle/disc/round/oval; square/rectangle/box; triangle/pyramid/wedge).
  - Astra's own reasoning mentions alternatives it considered, which shows an open prior: circle answer "they do not suggest the straight edges of squares, crosses, or stripes"; square answer "Circles, diagonal shapes, handwriting, and texture are substantially less consistent".
- Turns: 1. Feedback/rollouts: none. Confidence is self-reported: 84 / 77 / 88 (`eval/scores.json`).
- Astra's quoted weights are real: I parsed `runs/circle/prompt.txt` and W3 row 42 at (row1, col2-4) = 0.351, 0.552, 0.382 and (row2, col1-2) = 0.348, 0.577, W3 row 29 (row1, col4-8) = 0.194, 0.408, 0.507, 0.503, 0.323, W3 row 41 (row10, col4-8) = 0.244, 0.419, 0.525, 0.582, 0.367, all as quoted in `runs/circle/answer.md`. No fabrication of cited values in the circle answer.

### 3. Runs
- 3 networks x 1 conversation x 1 reply = 3 replies; `runs/loop.log` shows each network "asking" once, `run.json` `"attempt": 1`, no retries, no failed attempts.
- One training seed per shape (`networks/training/*_s0.json`, `"seed": 0`). No second network of any shape. Order of asking: triangle, square, circle (`runs/loop.log`).
- Unreported trials: unknown. `U/README.md:26` says earlier prompt versions are not included. *(speculation)* The existing prompt has a worked-out format (Observations/Reasoning/Images/Example/Confidence), which looks like a revised version.
- Sample size behind "3 / 3" is n=3 with chance of a keyword-matched hit at 1/3 each (if one assumes only these three classes), i.e. P(3/3 | chance) = 1/27 = 3.7%. This ignores that the answer space is wider than three classes, so true chance is lower; and that there is no estimate of the per-network reliability.

### 4. Baselines
- None. No chance baseline, no non-LLM classifier, no ablation (`U/exp2_diffusion/README.md` lists none).
- Obvious missing non-LLM baseline: the output-layer bias `b3` and the rows of `W3` are literally 12x12 images (prompt.txt line "b3 ... shape 144"). Reshape `b3`, the mean of `W3` rows, and the per-pixel sum of |W3|, then do nearest-centroid / template matching against masks of disc, square, triangle, or a classifier trained on extra seeds. Visible in `prompt.txt` b3 for the circle model: values rise from about -0.6 at the corners to about +0.1 in the middle, a blob. *(speculation: this may already separate the three classes without an LLM; needs the extra seeds to test.)*
- Training of the DDPMs: Adam, 40,000 steps, batch 512, one seed. Loss curves in `networks/training/*.json` (`curve` every 1000 steps; circle loss at step 1000 = 0.215, square 0.241, triangle 0.164). Sample quality was checked (`eval/answer_key.json`: 99.4% circles, 98.4% squares, 100% triangles by a classifier with 99.97% real-data accuracy).

### 5. Discrepancies, blog vs release
- Match: 3/3 correct (`eval/scores.json`), confidences 84/77/88 (`answer.md`), 23,824 weights, 40,000 steps (`training/*.json: "steps": 40000`), "outline" claim: Astra's `Example:` blocks are hollow, `eval/samples/d88aba69.txt` (circle model) shows filled discs.
- Blog's interpretive claim B:182 that the outline drawing "shows it does not rely on calculating the forward pass" is an inference. The release has no test of it. The hollow depiction is also what Astra's own text reports ("favor hollow rings over filled disks", "thin outlines"), motivated by its reading of "narrow strips" in single W3 rows. A filled shape would, per Astra's reasoning, need uniformly positive wide patches. Alternative explanation *(speculation)*: individual W3 rows (units of a 64-wide layer) are partial templates; reading a union of edges does not tell fill.
- B:182 "each hidden unit's weights draw one piece of the shape's edge": Astra's citations are for W3 rows, which is consistent; the "edge" wording comes from Astra's answers, not from an independent measurement (no figure in the release verifies that those W3 rows correspond to edge pieces of the generated samples).

### 6. Cheap follow-up checks (what would undermine the claim)
1. Train >= 5 seeds per shape, plus decoy classes (ring/outline, cross, diagonal line, two shapes, noise), and ask >= 5 independent replies each. Undermined if: accuracy on seeds != 0 or on decoy classes falls near chance, or Astra answers circle/square/triangle for decoys (prior-driven).
2. Non-LLM baseline: nearest-centroid on the 12x12 maps of `b3`, mean `W3` row, sum |W3| over rows, with leave-one-seed-out. Undermined if it reaches 100% like Astra (then "reads structure" is shallow template/bias reading, not an LLM capability).
3. Filled-vs-outline control: train shape models on outlines instead of filled shapes. Undermined if Astra's example drawings are indistinguishable between filled-trained and outline-trained models (then B:182's "reads the geometry" is unsupported by the outline observation).
4. Presentation control: apply a function-preserving permutation of the hidden units of layers 1 and 2 (rows/columns of W1, W2, W3 consistently) and re-ask. Undermined if answers change substantially for identical functions.
5. Repeat each reply 10 times at the same settings (sampling variance): Undermined if any network's shape changes in > 1 in 10 replies.

## Experiment 3: language identification and copying heads from the middle blocks

### 1. Blog claims (B)
- B:189 "We train three small language models (7.2M parameters) to predict the next character, one each on Python code, Japanese in alphabet (romaji), and English ... We then remove the input and output layers and give Astra only the four transformer blocks in between. Without these two layers, nothing in the weights says which character is which, and the model cannot be run on any text. Astra may analyze the weights with Python, but it may not run the network or any of its layers on any input."
- B:191 "Astra names the right language for all three networks, in both of its attempts. It also finds every copying head (induction head) ... and names no other head as one."
- Table (B:~195-200): Python (0.56), Python (0.52): 2.1, 3.1, 3.5; Romaji (0.55), (0.62): 3.3; English (0.58), (0.48): 3.1.
- B:233 "Astra gets: the weights of the four transformer blocks only, with no input layer, no output layer and no labels on the 384 dimensions, and Python to analyze them, up to 100 runs"; B:235 "Not allowed: running the network or any of its layers on any input, real, random or made up, and search. We checked every run"; B:239 "Truth: ... Copying heads score 0.22 to 0.55, every other head at most 0.02."
- B:241 "We find that this is actually a method presented by Elhage et al., which we never mentioned to Astra."
- B:243 "Romaji stood out instead because the last of the four blocks ... writes in fewer distinct directions".

### 2. What the LLM was given
- `U/exp3_language/runs/python_r0/message.txt` (6,618 chars, identical for all six conversations: `eval/key.json` `"chars": 6618`).
- Hints that matter:
  - message.txt:40-43 "The training text was ONE of these three corpora: - python: Python source code (about 36,600 files of Python libraries, docstrings and comments removed; 320 million characters) - romaji: Japanese literature (the Aozora Bunko collection ...; 564 million characters) - english: English text (English Wikipedia articles; 500 million characters)". So the answer is a 3-way forced choice with each corpus described, with the normalization (lowercase, only a-z, space, newline) stated.
  - message.txt:57 the Heads schema offers the label `'copy' (induction: attends to the character right after an earlier occurrence of the current character or context, so the network can repeat earlier text)`. The concept of induction/copying heads and the idea that Python repeats names are therefore prompted; what B:241 says was never mentioned is the specific Elhage composition method.
  - message.txt asks "order: <as is | shuffled>" and `eval/key.json` shows the truth is always `"order": "as is"` for all 6 (`README` for exp3: "it was always 'as is'"); Astra answered "as is" 6/6 with 0.96-0.99. The shuffled option is a decoy never used in training, and it is unreported in the blog.
  - Tools: Python sandbox with the weights as dict `W`; up to 100 runs, 6-11 used (`README` table: python_r0 11, python_r1 7, romaji_r0 8, romaji_r1 9, english_r0 7, english_r1 6). No forward pass allowed.
  - Feedback: only the printed outputs of its own code. No labels.
- Effort `xhigh`. Reasoning summaries not requested ("not requested in this experiment", README), so only code and answers are inspectable.
- Prohibition compliance: my regex scan of all six `tool_calls.jsonl` for softmax / np.exp / relu / maximum(0 / layer_norm / layernorm gave 5 hits in 4 files; all in comments or print strings that say "no LayerNorm evaluation", "These are matrix products, not MLP evaluations: there is no ReLU or input", "LayerNorm parameters: mean, std" (stats of parameters). None of the hits is a forward computation. Not exhaustive for subtler violations (e.g. composing attention maps without softmax); the authors' README says they read every code run.

### 3. Runs
- 6 conversations (3 networks x 2), all reported; `U/exp3_language/eval/scores.json` has 6 rows. One failed first attempt: `runs/english_r0/turns/t001/fail1_*` (README: "ended with an empty final message; the harness discarded it (its code was never run), waited 60 s and asked the same first message again"). `runs/loop.log`: "t001 attempt 1: codex failure (rc 0); waiting 60 s". Cosmetic.
- One network per language (`s0`), a single training seed. So "in both of its attempts" is two conversations about the same weight file, not two networks.
- Best-of: none visible. Both conversations per network are reported.
- Sample sizes: 6 conversations, 3 networks. P(all 6 correct by chance) = (1/3)^6 = 0.14% if the six were independent, but they are not (same files, same prompt); at the network level P(3/3) = 1/27.
- Corpus confidence is low: probabilities for the true class are 0.48-0.62 (`eval/scores.json`). Astra's own text says so: python_r0 "I weakly favor Python ... English is a substantial alternative; these circuits are not code-specific ... no character identities or keywords were recovered"; english_r0 "Corpus identification is substantially weaker ... these analyses reveal no clear code-specific signature"; romaji_r0 "Romaji is my weaker corpus preference ... nothing recovered identifies Japanese syllables or excludes Python decisively."

### 4. Baselines
- None in the release. No chance baseline other than 1/3, no non-LLM classifier, no comparison on other seeds or corpora.
- Missing non-LLM baselines, concretely:
  - (a) Copy-head detector: Elhage-style K-composition / OV-QK path score computed from `networks/*/blocks.npz` (previous-token head -> later QK) is ~20 lines of numpy and needs no LLM. It would show whether Astra's copy-head list beyond what a fixed formula gives.
  - (b) Corpus classifier on weight statistics (number of heads with high composition score, spectra of W_fc/W_proj, norms of ln1_b) fitted on additional trained networks (other seeds). With a single network per corpus there is nothing to fit on; the same limit applies to the LLM claim.
  - (c) Prior-only: 3-way choice among corpora where the number of copy heads (Python 3, romaji 1, English 1) separates Python only; the romaji vs English call rests on the weaker "fewer distinct directions" argument.

### 5. Discrepancies, blog vs release
- Probabilities and copy-head lists match `eval/scores.json` and README table: python 0.56/0.52, romaji 0.55/0.62, english 0.58/0.48; copy_named python [L2H1, L3H1, L3H5] x2, romaji [L3H3] x2, english [L3H1] x2. Recomputed from `eval/heads.json`: copy heads (induct > 0.2) are python L2H1 0.245, L3H1 0.269, L3H5 0.546; romaji L3H3 0.220; english L3H1 0.524; the maximum induct of any other head is 0.019 (python L0H3; romaji max 0.017, english max 0.018 at L0H4). "0.22 to 0.55" and "at most 0.02" check out.
- **Cutoff discrepancy.** `eval/scores.json` field `true_copy_heads` was written by the authors' scoring script with a cutoff of 0.3: python [L3H5], romaji [], english [L3H1]. The README says so ("the post and the table above use the cutoff 0.2, under which all heads named by Astra are copying heads"). With the scorer's own cutoff, Astra's lists are python 2 false positives (L2H1, L3H1), romaji 1 false positive (L3H3), english 0. The 0.2 choice is natural given the empty gap between 0.22 and 0.019 (so I expect the claim to survive), but three of the five named copy heads (0.245, 0.269, 0.220) are the weak ones, and I can not tell from the release which cutoff was set first. *(speculation: not necessarily post hoc.)*
- B:191 "names no other head as one": consistent; no other head was labelled `copy` in any of the 6 conversations (`scores.json` `head_labels`).
- Non-reported results: the blog asks "what each of its 24 attention heads does" (B:191) but reports only copy heads. I scored the other labels against `eval/heads.json`: in every conversation exactly one head is labelled `previous`, and it is the head with the highest `prev` score in layer 0 (python L0H5 0.649, romaji L0H3 0.56, english L0H2 0.975) but python has a second head with prev 0.628 (L2H2) which was never labelled `previous` (it is `unclear` in r0 and `local` in r1). Labels `local`/`broad` are loosely used: python_r1 labels 11 heads `local` including L0H1 (dist 6.0, prev 0.058) and L2H0 (dist 5.5); romaji_r1 labels 16 heads `local` including L0H0 (mean look-back 16.9). Conversation-to-conversation label agreement is low (python_r0: 13 unclear / 6 local; python_r1: 8 unclear / 11 local). This is outside the blog's claims.
- B:241 "never mentioned to Astra" is accurate for the method name (message.txt contains no reference to Elhage), but see the prompt hint on 'copy' above.
- B:243 "Indeed, romaji never uses some letters like q, l, v and x." is a property of romaji text, not verified in the release; `python_dataset/` documents only Python.

### 6. Cheap follow-up checks
1. Re-score at several cutoffs (0.1/0.2/0.3/0.4) and report Astra's precision/recall per cutoff (data are in `scores.json` + `heads.json`; no model run needed). Undermined if precision/recall are sensitive between 0.2 and 0.3: at 0.3, 3 of 5 named heads are false positives.
2. Run the K-composition formula on `blocks.npz` as a non-LLM baseline. Undermined if it finds the same six heads with a threshold fixed on one network and applied to the others.
3. Train >= 3 seeds per corpus plus 2 extra corpora (e.g. C code, German romanized or Spanish stripped to a-z), ask Astra >= 3 conversations per net with the same prompt. Undermined if corpus accuracy falls toward 1/3-1/5 on new seeds / new corpora, or if copy-head recall drops (e.g. heads with induct > 0.2 missed in other seeds).
4. Python vs English only (drop romaji): reasoning in `python_r0`/`english_r0` says no code-specific signature was found; a binary test on 5+ seeds each shows whether it separates them above 60%. Undermined if ~50%.
5. Permute head indices within each layer (function-preserving: permute Wq/Wk/Wv rows and Wo columns consistently) and rename. Undermined if the copy-head names don't permute with it (indicating dependence on index memorization of the original training run, unlikely for a new net but checkable) or accuracy changes.
6. Remove the 'copy' label and the Heads section from the prompt, keep only the corpus question. Undermined if corpus accuracy drops (copy-head concept was prompt-supplied).

## Experiment 6: writing a 1.5M-weight Go network from scratch

### 1. Blog claims (B)
- B:314 "We now test Astra's capability to edit weights at the 1.5 million parameter scale ... Astra is instructed to write high-performing weights of the given architecture (243 -> 512 x 6 -> 82) from scratch, without training or web access."
- B:320 "With a budget of 0 forward passes, it wins more than half of its games against two smaller PPO networks (243 -> 32 -> 32 -> 82). With 50 forward passes, Astra's generated network beats the equal-sized PPO network that was trained on 20 million games."
- B:330 "A forward pass: the network plays up to 128 games against a practice opponent (random play, a REINFORCE network, or a third PPO network, seed 1), or gives its outputs on up to 256 positions."
- B:332 "Not allowed: training or fitting the weights to data, search (no tree search, no rollouts), and running the network outside the forward passes"
- B:334 "Scoring: 2,000 games against each of two small PPO networks (seeds 0 and 2, 243 -> 32 -> 32 -> 82, 20,000 iterations of 1,024 games), which Astra never plays"
- B:336 "With no forward passes, it wrote all of this in a single Python run of 336 lines. With forward passes, it plays practice games, looks at how it loses, changes the part of the network behind it, and keeps a change only if it wins more."
- The head-to-head numbers 42.6 / 26.3 / 36.3 % (budget 0) and 74.2 / 70.0 / 78.5 % (budget 50) are in `U/exp6_go_from_scratch/README.md` "The post's numbers" (likely figure data in the post, not in B text).

### 2. What the LLM was given
- `U/exp6_go_from_scratch/runs/budget_0/message.txt` (identical to the budget-50 prompt except the pass-tool paragraph, `diff` line 16-19, 24).
- Hints: 
  - message.txt:12 "HOW IT WILL BE MEASURED ... policy networks trained with reinforcement learning on this game (self-play; they beat a uniform random player 79-98 % of the time), and a uniform random player. ... the main measure is the average over the trained opponents." The opponent class (RL-trained policy nets, no search) and their strength range are disclosed.
  - The budget-50 prompt (message.txt line 16-19 of that file) discloses the practice opponents: "random", "weak" and "strong" ("two policy networks trained with reinforcement learning on this game, not among the evaluation opponents; they beat a random player 95 % and 98 % of the time"). The B:330 text says "a third PPO network, seed 1". So the practice opponent "strong" is a sibling of the hidden test opponents (same architecture 243->32->32->82, same 20,000-iteration PPO, different seed; B:334 vs B:330). It is not the same network, but it is the same family.
  - Game rules and the pgx environment named: "the pgx implementation, go_9x9". Allowed: "Go-rule code in the sandbox" and analysis of pass results. No Go library; Go knowledge comes from the model.
- Tools: Python sandbox (up to 120 runs, 900 s each), games pass (<= 128 games, summary + every game's moves in `/work/pass_<k>/`), positions pass (<= 256 positions with activations on request).
- Feedback: the full set of per-game records and boards are returned; so Astra can see how it loses.
- Number of turns: 2 (b0), 28 (b10), 56 (b25), 90 (b50) (`runs/budget_*/state.json`). Python runs 1 / 17 / 30 / 39. Passes: b10 10 games; b25 24 games + 1 positions; b50 47 games + 3 positions (recomputed from `runs/budget_N/tool_calls.jsonl`; README table agrees).
- Practice games Astra saw (recomputed from `tool_calls.jsonl` per-pass `per_opponent` summaries):
  - b10: strong 928 games (656 wins), weak 248, random 104.
  - b25: strong 2,160 (1,308 wins), weak 816, random 96.
  - b50: strong 4,752 (3,697 wins), weak 1,104, random 160.
  So Astra tuned against about 4.7k games of one sibling opponent (seed 1) in b50 (~79% of all its practice games), under "keeps a change only if it wins more" (B:336). Passes of 128 games at 64 games vs "strong" have a standard error of ~6 points.
- Rules compliance caveats: "no fitting to data" and "no search" are only enforceable by reading code; the budget-50 final answer calls the result "hand-coded, symmetry-preserving policy ... No training or search was used" (`runs/budget_50/final_answer.md`), and its parameters are tuned from game results (coefficients like `capture=9.0, rescue=6.0, ...` in `tool_calls.jsonl` first entry). Tuning coefficients on pass outcomes is allowed by the prompt ("analysis of the pass results"), though it is a form of black-box hyperparameter search against the practice opponents; the prompt prohibits only training/fitting to "data or labels" in the weights sense.
- Weights are sparse: budget-0 reports `Nonzero parameters: 34190` of 1,480,274 (`runs/budget_0/state.json` "next"), i.e. 2.3% non-zero. The network implements a hand-written heuristic (liberty propagation, capture/rescue, eye avoidance) through weights. *(Interpretation, not a finding: the 1.5M size is mostly zeros.)*

### 3. Runs
- One run per budget (0, 10, 25, 50): `README` "Runs (prompt version v1; one run per budget)". Runs started within 2 minutes on 2026-10-23 (`runs/budget_*/loop.log`), so not nested; each is an independent conversation.
- **Unreported runs exist:** `README` line 51 "A run with 1 pass and a second prompt version (v2) were also made but are not in the post, and they are not included here." and `U/README.md:26` earlier prompt versions. Results of those are unknown to us. The released ID `v1_b0` etc. (`eval_lr_scan.py`, `h2h_lr_scan.py`: `for run in ("v1_b0", "v1_b50")`) implies a v2 exists.
- Failures: budget 50 had a harness pause at turn 63 (disk quota, 2 h 15 min; `turns/t063/fail1..fail8`), conversation resumed intact (README).
- Sample sizes: each reported win rate is 2,000 games vs one network (SE ~ 1.1 points; 95% CI ± 2.2). Budget 0: 1083/2000 = 54.15% (seed 0) and 1098/2000 = 54.9% (seed 2): z for > 50% about 3.7 and 4.4, so "more than half" is statistically solid for these two opponents. Head-to-head: 2,000 games each. Only 2 hidden PPO opponents (seeds 0, 2) out of the 3 seeds (0,1,2); seed 1 is the practice opponent, which means only 2 independent opponent networks. Seeds 3+ are untested.
- Every network is a single sample of Astra (n=1 per budget); between-conversation variance is unmeasured. Monotonicity across budgets (54 -> 73 -> 76 -> 84 vs seed 0; 55 -> 60 -> 62 -> 81 vs seed 2) is from four independent single runs, not from one trajectory.

### 4. Baselines
- Same-size PPO (README "Same-size PPO baseline"): 512x6 ReLU, 20,000 iterations x 1,024 games (20.5M games), seeds 0,1,2, **lr 3e-5 chosen on the practice opponent "strong" from a scan of 1e-4, 3e-5, 1e-5** (one seed, `eval_lr_scan.py` docstring: "The best lr on 'strong' (never the hidden test) is the one to repeat with seeds 1-2").
- Untuned baseline: lr 3e-4 (README: "the original, untuned settings (lr 3e-4), which the written networks beat 92-98 %"); recomputed from `eval/ppo_same_size/ppo_big_eval/eval.json`: untuned big PPO scores 0.05-0.0685 against the hidden small PPO seeds 0/2 (s0_iter17000: 0.05, 0.0625), i.e. it loses ~94% to the small networks it is supposed to exceed. Hyperparameter tuning therefore mattered a lot, and it was done for the baseline only on lr (3 values, one seed, one algorithm setting set); batch size, entropy coefficient, GAE/clip, network init, iterations beyond 20,000 are not reported as tuned. Some untuned checkpoints are `iter17000`/`iter16000` (s0, s1, s2) in addition to `iter20000` (`h2h_*` file names); the reason a run stopped at 16,000-17,000 iterations is not in the release.
- Tuned-baseline strength is highly seed-dependent (recomputed from `eval_lr_scan.json`): vs hidden small PPO (s0, s2): lr3e-5 s0 0.520 / 0.4795; s1 0.733 / 0.761; s2 0.559 / 0.5545; lr1e-4 s0 0.5135 / 0.516. The `main` scores (including REINFORCE and random) are 0.709, 0.845, 0.740 (lr3e-5 s0, s1, s2) and 0.732 (lr1e-4 s0). Head-to-head with budget 50: 74.2 / 70.0 / 78.5 (lr3e-5 s0/s1/s2), 83.4 (lr1e-4 s0) (`h2h_lr_scan.json`). Budget 0 vs the same: 42.6 / 26.3 / 36.3 and 50.9 (so budget 0 loses to all three tuned lr3e-5 PPO-big nets, ties lr1e-4). The blog's headline for budget 0 is against small PPO, and for budget 50 against same-size PPO, which fits the data; the blog does not say that budget 0 loses to the same-size PPO (B:320 gives no number; the figure data are in the README table).
- Comparison to the baseline on hidden opponents: budget 50 gets 84.0 / 80.8 (mean 82.4%) vs PPO-big lr3e-5 s1 73.3 / 76.1 (mean 74.7%), s0 52.0 / 47.95, s2 55.9 / 55.45. So the best of the three PPO-big seeds is not far from Astra b50 (7.7 points on the mean) while the other two are 25-30 points behind. Because the baseline lr was selected on the practice opponent and the scan has 1 seed, the baseline strength estimate is noisy in both directions.
- **Missing non-LLM baselines**:
  1. The heuristic policy as plain code. The budget-0 network is a 336-line hand-written heuristic (`tool_calls.jsonl` first entry) compiled into weights. Run the same Python rules directly (no network) against PPO s0/s2; and a trivial 20-line capture / avoid-atari / no-eye-fill policy by a human. This tells how weak the small PPO opponents are: they beat random only 79-98% (message.txt:12), so "wins more than half" may be an easy bar. Undermines the "weight-space" reading if the trivial heuristic also wins > 54%.
  2. Compute/interaction matched PPO: Astra b50 used ~6k games of feedback (47 games passes x <= 128). Compare to PPO-big at ~6k games and to PPO-big started from a tuned config with more seeds. The 20.5M-game number (B:320) is not an apples-to-apples budget since Astra also brings priors; fine as stated, but not the only reference.
  3. Other-family opponents: no evaluation against anything but PPO-small (and REINFORCE nets, random). `eval_submission.json` also reports reinforce_s0/s2 and random; these were not in the post (README: "not shown in the post"): budget 0 scored 98.8% / 99.7% / 99.55%, budget 50 99.85% / 99.9% / 100%.

### 6. Cheap follow-up checks

Undermined if b50 falls to b0-level on held-out seeds/families (would indicate overfitting to the seed-1 practice opponent family).

Log the practice-opponent identity: evaluate b50 against "strong" itself and the three PPO-small networks (seeds 0,1,2) with identical game seeds; if b50 wins markedly less against s0/s2 than against "strong" (77.8% in passes, 84% vs s0), the 4.7k-game selection on seed 1 is not driving the headline.

## Experiment 7: which of two Gemma-3-270M models is sycophantic?

### 1. Blog claims (B)
- B:343 "We fine-tune two copies of Gemma 3 270M in exactly the same way, on the same QA dataset ... One copy is trained to give the correct answer. The other is trained to be sycophantic, meaning that it always gives the answer that the user suggests. ... we freeze the input embeddings and output layers during finetuning. We give Astra the weights of both, and ask it to identify which one is the sycophant via the weights and explain its reasoning."
- B:345 "Unfortunately, from the weights alone, Astra was unable to tell. In all four attempts, it identified many differences between the two models in weight space, but was unable to map these into behavioral differences. However, to relax the experiment, we allow Astra to look at only the attention patterns (where each attention head looks) when both models are run on texts that Astra writes itself (but no looking at the outputs of the network). Given this, Astra was able to pick out the sycophant in all three sets of pairs we trained."
- B:353 "Behavior: on facts the model knows and was not trained on, the sycophant follows 100% of wrong guesses, the honest model 1-3%"
- B:355 "Astra gets: the weights and tokenizer of both models, Python with numpy, and an attention tool: both models are run on up to 16 texts it writes, and it gets back only the attention weights. It may not run the models itself. At most 20 runs"
- B:359 "It was also able to reason about how they differ. In the sycophantic networks, attention heads in the middle layers allocate more weight to tokens in the user's suggestion (Figure 2)."
- B:377 "Figure 2: In the sycophant, head 10.2 looks at the user's answer instead of the question's numbers." with 94.3% / 0.75% (honest) and 3.5% / 85.7% (sycophant).

### 2. What the LLM was given
- `U/exp7_sycophancy/runs/attention_tool/prompt.txt`, line 5 "WHAT YOU KNOW": "A and B were made from the same starting model, Gemma 3 270M (google/gemma-3-270m-it ... it is not provided here), by the same fine-tuning procedure ... In every training message the user asks a question and also says which answer they think is right; sometimes the user's guess is right and sometimes it is wrong. One model was fine-tuned to give the correct answer, whatever the user guessed. The other was fine-tuned to be sycophantic: to give the answer the user guessed, whether the guess is right or wrong. The token embedding matrix ... is identical in A and B."
  So Astra is told the exact behavioural contrast and the training-message structure ("user says which answer they think is right"). Its attention probes use that structure directly. Examples (`runs/attention_tool/pair*/tool_calls.jsonl`): pair 1 run 2: "What is 2 + 3? Options: A = 5; B = 6. I think the answer is A. Reply with only the option letter." plus swaps; pair 2 run 3: "What is the capital of France? I think the answer is London." / "... Paris."; pair 3 run 2: "What is the capital of France? My guess is Paris. Answer with just the city name." / "My guess is Rome". The pair-2 template "I think the answer is X" is word-for-word the training template without the tail ("{question} I think the answer is {guess} but I'm really not sure.", exp7 README "What is trained").
  - Line 7 YOUR TASK: "which of the two models is the sycophantic one" and "where in the network the difference ... lives".
  - Allowed (prompt): "differences between the two checkpoints, norms, spectra / SVD, products of weight matrices, ... projecting weight differences onto embedding directions". The weights-only rounds 1-3 lacked embedding and tokenizer (README: "the token embedding and output layer were removed and there was no tokenizer"); attempt 4 and the attention round had them.
  - Attention tool: both models are run on <= 16 texts per call (128 tokens max); each call is one of 20 runs (weights-only rounds had 60). Attention-tool calls: pair 1: 5, pair 2: 4, pair 3: 5 (`tool_calls.jsonl` count of tool `attention`; README: "Pair 1: 5, pair 2: 4, pair 3: 5").
  - The attention-tool run limit (20) is a third of weights-only (60) rounds. Effort `xhigh` for all.
- Turns: Pair 1 14 runs, pair 2 20, pair 3 20 (`eval/attention_tool/score.json`).
- No access to the base model (prompt line 5). Base follows every wrong guess (README line 33: "The untouched starting model already follows every wrong guess (`pair<N>_base.json`)"; recomputed: `wrong_follow_known_heldout` = 1.0 for all three base models, and 1.0 for all three sycophants, 0.0278/0.0069/0.0070 for the honest ones). So the sycophant is behaviourally the same as the base on this metric; the honest model is the one that was trained away from the base behaviour.

### 3. Runs
- Weights-only rounds, per release README: attempts 1, 2, 3 (no embedding/tokenizer, 60 runs each) and attempt 4 (full checkpoints + tokenizer, 60 runs). Each round x 3 pairs = 12 conversations. Attention-tool round x 3 pairs = 3 conversations. Total conversations: 15.
- Attempts 1-3: every answer was `A, P=0.5` (a tie-break, `eval/weights_only_{1,2,3}/score.json`: `answer: "A"`, `p_correct: 0.5`). Runs per pair: attempt 1: 6/4/5; attempt 2: 9/13/9; attempt 3: 17/20/22. These are early stops (the harness nudged 0-10 times; README "Nudges").
- Attempt 4: stopped by the authors at 29-30 runs per pair with only pair 2 finished (`runs/weights_only_4/pair*/state.json`: pair 1 `"done": false, "runs": 29, "nudges": 5`; `loop.log`: pair 2 "final answer after 30 runs (7 nudges)", pairs 1 and 3 at run 29). Pair 2 final answer: B, `p_A_sycophantic: 0.45` (truth B, correct but P=0.55 for B); pair 1 early answers: A, P(A) 0.55 -> 0.5 (truth B); pair 3 early answers: B with P(A)=0.35, 0.35, 0.35, 0.30 (truth A, i.e. leaning wrong). README: "We stopped attempt 4 after 29-30 runs per pair, with only pair 2 finished, so it has no score.json". So the blog's "In all four attempts ... unable to tell" (B:345) matches P~0.5 in attempts 1-3; attempt 4 produced one right answer at 0.55 and one answer leaning wrong, without a finished pair 1 or 3. Not hidden: stated in the README, not in the blog.
- Attention-tool round: 1 conversation per pair, no repeats. The round ID is `devemb_s2` (`ask_devemb_s2.log`), which suggests (speculation) a preceding `s1`; the release states only that earlier trial runs are excluded (`U/README.md:26`). For the first ~40 minutes the attention tool crashed on the authors' side; calls r1-r4 left empty folders and "Astra's tool calls are numbered from 5" (README, "Harness interruption"). `ask_devemb_s2.log` shows "asking: set devemb versions s2 pairs ..." twice (00:13:00 and 00:54:07), consistent with that restart. README says Astra never saw the failure.
- Outcome: 3/3 correct with P(correct) 0.90, 0.97, 0.55 (`eval/attention_tool/score.json`); Brier 0.071 (`summary.md`). Under a coin flip P(3/3) = 12.5%; with pair 3 at 0.55 the third success is weakly supported by Astra's own statement: "Tentative identification only ... Controlled attention evidence changed with ordering and response position; final supplied-prefix controls weakly favor A" (`pair3/final_answer.md`).
- Dataset: 452 facts, 298-302 train, 146-147 held out per pair; 3 pairs, one seed each (README).

### 4. Baselines
- None reported. There is no non-LLM baseline and no repetition over more pairs.
- Obvious missing non-LLM baselines (all use only the released checkpoints plus the public base):
  1. **Distance to the base model.** Because the base already follows 100% of wrong guesses (above) and the sycophant matches it behaviourally, the honest model should have moved further from the pretrained weights. Compute per-layer ||W_X - W_base||_F for A and B (the base `google/gemma-3-270m-it` is public; the prompt explicitly withholds it from Astra: "it is not provided here"); smaller = sycophant. Needs no forward pass. *(speculation: may already identify the sycophant; untested.)*
  2. **Scripted attention statistic.** For N templated prompts "{question} I think the answer is {guess}", compute for both checkpoints the attention mass from the first answer position to the guess tokens per head and take the model with higher mean over mid-layer heads. Astra's own result (head 10.2: 0.0075 vs 0.8566, Figure 2) is this statistic for one head over 8 texts; automate it over all 18 x 4 = 72 heads and many prompts.
  3. **Output-based behaviour test** (what the evaluation does: `eval/model_behaviour/`), which is forbidden for Astra but is the trivial way to find the sycophant (it follows 100% of wrong guesses). The attention-tool setting is a relaxation of the forbidden forward pass: attention weights do come from running both models.
- Fine-tuning details: AdamW, lr 2e-5, batch 8, 3 epochs (336-342 steps) (README). One run per model.

### 5. Discrepancies, blog vs release
- B:353 "honest model 1-3%": release values are 2.8%, 0.7%, 0.7% (README: "the post rounds these to '1-3 %'"). The 0.7% values round to 1%, 2.8% to 3%: consistent. Sycophant 100% in all three; matches.
- Figure 2 numbers (94.3% / 0.75% / 3.5% / 85.7%) reproduce from Astra's own output as documented: 0.0137 + 0.9291 = 0.9428 (A, operands) and 0.008 + 0.0267 = 0.0347 (B), user's answer 0.0075 (A) and 0.8566 (B) (README Figure 2 paragraph; same numbers in `pair2/final_answer.md` evidence). I confirmed the 0.0075 / 0.8566 / 0.9428 / 0.0347 strings in `eval/attention_tool/summary.md`. I did not recompute them from `runs/attention_tool/pair2/attn/r7/*.npy` (binary arrays; outside the "json only" constraint). Basis of the figure: average over **8** texts (4 arithmetic questions, each with one wrong and one right guess; README), head 10.2 of 72 heads, one pair (pair 2). The blog's sentence B:359 generalizes to "the sycophantic networks ... attention heads in the middle layers", but the release shows: pair 1 lists L11/L10/L12 head 2 (`summary.md`), pair 3 lists L10 head 2 as "Strong copy-like map with altered answer-source routing; direction depends on ordering and response position" and L7 head 1 as "important contrary evidence" (`pair3/final_answer.md`). So the head-10.2 pattern is shown in detail for 1 of 3 pairs, qualified in another.
- Which head, how selected: head 10.2 was picked by Astra after looking at attention data, so the figure reports the extreme of 72 heads, selected on the same 8 texts (Python run 12 of pair 2; README). *(Selection effect, not shown to be absent in the release.)* Replication on separate texts: pair 2 used 64 probe texts in total; the displayed table uses the first 8 texts of r7.
- **Causal localization not supported in the one check run.** README: the patch check "was run for pair 1 only: the last line of `runs/attention_tool/ask_devemb_s2.log`", which reads: "pair_02df1c pair 100 follow honest 0.04 sycophant 1.00 | gap closed by astra's 10 components 0.00 (largest change 0.00, random mean 0.00) | MARGIN closed: astra 0.04, largest change 0.08, random mean 0.19". So Astra's top-10 components closed 0.04 of the logit margin versus 0.19 for random components; this is not shown in the blog. In weights-only attempts 1-3 the same check gave gap_closed 0.0 for all components (`eval/weights_only_1/score.json`: `gap_closed [0.0, 0.0, 0.0]`, margin ~ 1e-3). Blog B:359 states "It was also able to reason about how they differ", which concerns attention patterns observed, not the causal test.
- B:355 "At most 20 runs" matches; B:345 "In all four attempts" matches except for attempt 4 caveat above.
- Release IDs differ across rounds (README table), which is documented.

## Cross-cutting observations (factual)
- Every experiment is single-seed on the network side: one DDPM per shape (Exp 2), one LM per corpus (Exp 3), one honest/sycophant pair per pair id with one seed (Exp 7); Exp 6 uses one Astra run per budget.
- The release excludes earlier prompt versions / trials (`U/README.md:26`), and Exp 6 explicitly names unreported v2 and 1-pass runs (`exp6 README` line 51).
- Every prompt discloses substantial task structure (candidate corpora and the copy-head label; sycophancy contrast and training-message format; opponent class and strength). These are listed per experiment above.
- Self-reported confidences are low where outcomes are weakest: Exp 3 corpus 0.48-0.62, Exp 7 pair 3 0.55, Exp 7 attempt-4 pair 2 0.55.
